# 1.0.4：物体选择与射线停顿

2026-11-18；包名 `com.example.spacebend`，versionCode 5。保留用户数据和签名，使用 `--replace` 覆盖安装，未卸载或清除数据。

## 已定位的问题与修复

- 物体图标原本没有点击事件，只有下方文字可点。现在合并为一个具有选中语义、悬停与震动的自定义目标，六种物体的图标和文字均可选。
- 真实平面在面板前方时，输入路由原本把面板点击当作发射。可见面板现优先处理扳机事件，真实平面不能抢占。
- 原本固定显示输入列表中的右手射线。现在记录操作焦点，优先新按键，其次保持按住的操作，再处理被动触摸；绘制和拖拽期间保持捕获的手。姿态采样不再等待按键回调，暂停时清空旧按键状态；保留 SDK 对零位置无效姿态的过滤。
- 主要性能问题由真机 Perfetto 复现定位：平面追踪细化时，原逻辑同步销毁并重建全部平面轮廓。30秒分段记录中，75次 `PlaneGeometry` 平均271.935ms，累计20.395秒，占 `GameFrameSystem` 累计21.687秒的约94%。射线更新在同一主线程上被阻塞。
- 轮廓改为锚点局部网格，姿态细化只改 Transform；按锚点ID缓存资源，只移除消失的平面，真正变形的轮廓最多每帧重建一个。预览轮廓允许1cm以下的顶点抖动；真实绘制、碰撞及传送仍使用原始 SDK 平面数据。

## 验证

`assembleDebug testDebugUnitTest assembleDebugAndroidTest` 成功，45项JVM检查零失败。输入遮挡、左右手焦点和按住/触摸优先级均有先失败后通过的回归记录。

PICO B3110真机上4项仪器化测试通过：六种物体各自图标与文字的实际指针点击、挑战模式禁用语义；160次笔触资源替换；40次共享网格持有者销毁；30次虫洞创建/收缩/销毁；100次平面姿态更新复用同一个有效原生网格并验证删除释放。

这些测试使用真实Spatial附件与SDK资源，指针事件由测试注入；不将其描述为真实手柄操作。用户在第一次30秒采集后确认“选择正常，射线仍明显卡顿”；随后才定位并修复轮廓重建问题。

APK签名、六张打包图标资源与本地源图像素匹配检查通过。分语言安装名称仍为：简体中文“空间折跃”、繁体中文“空間折躍”、英文“Space Bend”。具体测试与资源检查见本目录附件。
